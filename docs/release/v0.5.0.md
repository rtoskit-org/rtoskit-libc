rtoskit-libc 0.5.0 is the first release of an ISO C23 (N3220) C standard library for small embedded systems. It targets Arm Cortex-M, from the Cortex-M0 to the Cortex-M7 and Cortex-M33, was written clean-room from the standard text, and reaches the operating system through one link-time interface, so the same archives run on bare metal or under any RTOS that implements it. It is licensed under the Mozilla Public License 2.0.

This is a 0.x release. The library is complete for its scope and every change to it has passed the full test suite on all seven architectures, but its ABI and its RTOS interface may still change before 1.0; see [Before 1.0](#before-10).

## Highlights

- **The C23 library a microcontroller can use**, including the C23 additions, `<threads.h>`, `<stdatomic.h>` and a complete `<math.h>`, `<complex.h>` and `<fenv.h>`.
- **POSIX threads.** `<pthread.h>` is in `libc.a`, written once over the RTOS interface, and `<threads.h>` is a thin layer over it.
- **Correct results.** `printf` and `strtod` convert exactly at any precision; the float maths functions are correctly rounded and the double ones below 0.53 ulp; floating-point exceptions are raised on every core, including those without an FPU.
- **Small.** One function per file and section, no hidden global state, its own soft-float helpers, and drop-in archives that trim `printf` and the allocator further. A size budget has gated every change since phase 2.
- **Fast when you ask for it.** A separate speed build with Thumb-2 string kernels, faster conversions and fixed-point maths on the cores without an FPU.
- **Usable from C++.** Every header compiles as C++ (the ones a C++98 program reaches as `gnu++98`), and the library provides the C++ ABI hooks libstdc++ needs.

## What is in the library

### ISO C23

Every clause 7 header is implemented except the wide-character headers (`<wchar.h>`, `<wctype.h>`, `<uchar.h>`), Annex K and decimal floating point. That includes:

- the C23 additions: `<stdbit.h>`, `<stdckdint.h>`, `memset_explicit`, `memalignment`, `strdup`/`strndup`, `strfromd`/`strfromf`/`strfroml`, `timegm`, `timespec_getres`, `%b` and the `wN`/`wfN` length modifiers;
- `<stdio.h>` with buffered, locked `FILE` streams over the RTOS interface, and the whole `scanf` family;
- `<stdlib.h>` with three allocators to choose from at build time (nano, the default; TLSF, for O(1) timing; tiny), growing the heap on demand (the speed build has an introsort `qsort`);
- `<time.h>` with a 64-bit `time_t` on every target and POSIX `TZ` rules; `<locale.h>` with the "C" locale;
- `<threads.h>` and `<stdatomic.h>`;
- `<math.h>`, `<complex.h>`, `<tgmath.h>` and `<fenv.h>`, with every rounding direction and exception flag on the cores whose FPU has them (and a soft `<fenv.h>` on the others).

`long double` is `double` on every target. The implementation-defined behaviour is documented clause by clause against Annex J in `docs/implementation-defined.md`.

### POSIX threads (`<pthread.h>`)

New in phase 10 (PLAN D148 to D157):

- threads: `pthread_create`, `join`, `detach`, `exit`, `self`, `equal`, and attributes for the stack (size, or a stack of your own), the detach state, the scheduling policy and priority, and inheritance; `pthread_setschedparam`, `getschedparam`, `setschedprio` and `sched_get_priority_min`/`max`, with a priority range per policy;
- mutexes: normal, recursive and error-checking, with priority inheritance (`PTHREAD_PRIO_INHERIT`) where the port supports it; `pthread_mutex_timedlock` and `clocklock`;
- condition variables with a chosen clock (`pthread_condattr_setclock`, `pthread_cond_clockwait`);
- keys (`PTHREAD_KEYS_MAX` is 32) with destructor passes, and `pthread_once`;
- read-write locks, barriers and spin locks.

Thread control blocks are not allocated by the library: `pthread_t` is the port's handle. `<threads.h>` now wraps these functions with C11's return codes. Left out on purpose: cancellation, `pthread_kill` and signals, `pthread_atfork`, process-shared objects (`PTHREAD_PROCESS_SHARED` returns `ENOTSUP`) and robust mutexes.

### A minimal POSIX subset

For RTOS ports and a hosted libstdc++ (PLAN D128): descriptor I/O (`open`, `close`, `read`, `write`, `lseek`, `fstat`, `fcntl`, `fileno`, `fdopen`), `clock_gettime`, `clock_getres`, `nanosleep`, `sched_yield`, `getpid`, `getentropy`, `strnlen`, `strcasecmp`, `reallocarray`, `sincos` and the `<sys/types.h>`, `<unistd.h>`, `<fcntl.h>`, `<sys/stat.h>`, `<strings.h>` and `<sched.h>` headers. These names appear in the ISO headers only when a POSIX feature macro asks for them.

### C++ support

- Every public header compiles as C++, with `extern "C"` linkage.
- `__cxa_atexit`, `__cxa_finalize`, `__cxa_thread_atexit` and `__dso_handle`.
- `__libc_call_once_eh`, an exception-safe `call_once` for `std::call_once`.
- `<rtoskit-libc.h>`: `__LIBC_HAVE_*` macros that tell libstdc++'s configure what the library provides.
- An optional unwind-tables build (`LIBC_UNWIND_TABLES=1`) so `std::stacktrace` can walk through library frames.

## Correctness

The conformance tests are the project's own, written from the C23 text. They took over every in-scope check of musl's libc-test, which the project used until all 219 applicable tests passed on all seven architectures. `make check` runs, on every architecture and in every build type:

- the header APIs, with every public header compiled alone under `-pedantic-errors`;
- the functional cases, and a regression case for every bug fixed;
- every maths function in float, double and long double, in all four rounding directions, with the exception flags, against vectors computed with MPFR;
- the threads, thread-local storage, C++ runtime and bare-metal (`port/none`) tests;
- a check that no program links a libgcc object in place of one of the library's own symbols.

An audit of the headers against Annex B checks 689 identifiers, 642 exact prototypes and 73 generic names across 28 headers.

| | rtoskit-libc | picolibc / newlib | Arm Optimized Routines |
|---|---|---|---|
| Float functions, round to nearest | Correctly rounded, checked over all 2^32 arguments on x86-64 and Cortex-M7. On soft-float and single-precision cores, a documented handful of hard cases are within 1 ulp. | fdlibm-style, up to about 1 ulp | 0.004–3.9 % of results misrounded per function, worst 1.09 ulp |
| Float functions, directed rounding | Correctly rounded | not measured | Up to 2 ulp |
| Double functions | Below 0.53 ulp, at most 0.023 % misrounded | Up to about 1 ulp | Below 0.53 ulp, except `erf` at 0.89 ulp |
| Floating-point exceptions | Raised on every core | — | None from AOR's Arm soft float |

| `malloc` / `free` heavy | 988 | 960 | 2156 |

1. Includes the soft-double helpers, which rtoskit-libc provides itself; the other two figures leave them to libgcc.

Current figures for every architecture are in `docs/size/<arch>.md`.

## Speed

Guest instructions per operation under qemu on a Cortex-M4F, as the geometric mean over each benchmark program, divided by the count for rtoskit-libc's `speed` build (below 1 is fewer instructions):

| Benchmark | `release` build | `speed` build | picolibc | newlib-nano |
|---|---:|---:|---:|---:|
| string (603 cases) | 1.51 | 1.00 | 1.48 | 1.18 |
| stdio (23) | 1.22 | 1.00 | 1.16 | 0.94 |
| `strto*` (21) | 6.17 | 1.00 | 1.00 | 1.77 |
| malloc (9) | 1.07 | 1.00 | 7.21 | 0.68 |
| maths, throughput | 1.00 | 1.00 | 0.39 | 0.42 |

The maths functions take more instructions than picolibc's and newlib's because they are correctly rounded, and `%f` and `%g` because they format exactly; newlib-nano's allocator takes no lock, while ours is always thread-safe. The method and its limits are in `docs/research/benchmarks.md`, and current figures in `docs/perf/<arch>.md`.

## Downloads

One archive per architecture, `rtoskit-libc-0.5.0-<arch>.tar.xz`. Each holds `release/` (the size build, the one to ship) and `speed/`, each with `include/` and `lib/`:

- `libc.a`, and the drop-in replacements `libc-nofloat.a` (no floating-point `printf`/`scanf`), `libc-minimal-printf.a` (no `%n` or 64-bit conversions) and `libc-tinymalloc.a` (the smallest allocator);
- `libm.a`, empty, so that `-lm` links (the maths functions are in `libc.a`);
- `librtos-none.a`, the bare-metal port (one thread), and `librtos-linux.a`, the Linux port the tests run on.

| Archive | Cores | Built with |
|---|---|---|
| `armv6-m` | Armv6-M without the OS extension | `-march=armv6-m -mfloat-abi=soft` |
| `armv6s-m` | Cortex-M0, M0+; also M23 | `-march=armv6s-m -mfloat-abi=soft` |
| `armv7-m` | Cortex-M3; M4 or M33 without an FPU | `-march=armv7-m -mfloat-abi=soft` |
| `armv7e-m` | Cortex-M4F; M7 with the single-precision FPU | `-march=armv7e-m+fp -mfloat-abi=hard` |
| `armv7e-m-dp` | Cortex-M7 with the double-precision FPU | `-march=armv7e-m+fp.dp -mfloat-abi=hard` |
| `armv8-m.main` | Cortex-M33 with FPU and DSP; also M55, M85 | `-march=armv8-m.main+fp+dsp -mfloat-abi=hard` |
| `x86_64` | the development host, through the Linux port only | `-mlong-double-64` |

The Arm archives were built with arm-none-eabi GCC 16.2, and all of them carry `-g3` debug information, which the linker drops. `SHA256SUMS` lists every archive's checksum, and each archive's build provenance can be checked with:

```sh
gh attestation verify rtoskit-libc-0.5.0-armv7e-m.tar.xz --repo sgstreet/rtoskit-libc
```

## Using it

- Compile your program as C23 (`-std=c23` or `-std=gnu23`; GCC 15 and newer default to `gnu23`) against the archive's `include/` only (`-nostdinc -isystem <dir>/include`), with the same `-march` and `-mfloat-abi` as the archive.
- Link with `-nostdlib`, putting the port, `libc.a` and libgcc in one `--start-group ... --end-group`, and use `--gc-sections`.
- On bare metal, `librtos-none.a` works as it is: your startup code calls `__rtos_none_start()` and your linker script gives the heap bounds. For an RTOS, implement the `__rtos_*` functions declared in `include/rtos/rtos-port.h` (locks and futexes, threads, scheduling, TLS, time, I/O, the heap and exit) and link your port in place of `librtos-none.a`.

`README.md` has the full commands and a GCC spec file that does all of this; `docs/configuration.md` describes the archives, cores, allocators and ports.

## Before 1.0

- **ABI.** Phase 10 changed the layout of `mtx_t` and `cnd_t` and the thread part of the RTOS interface (attributes, a `void *` exit value, scheduling, a time base for futex waits, priority-inheritance locks). A toolchain's libstdc++ and any RTOS port built against an earlier tree must be rebuilt against this release.
- **Consumers.** Building rtoskit-gcc's libstdc++ with the `posix` thread model (it needs `_GLIBCXX_GTHREAD_USE_WEAK 0`), and pi-pico's move to this library's threads, are still to be done (P7.05, P10.08).
- **Toolchains.** The library builds only with GCC 14 or newer; compiling programs against it with Clang 19 or newer is untested.
- **Architectures.** Only the seven architectures above; the other Arm profiles and AArch64 are planned (phase 6).
- **Out of scope:** wide characters, Annex K, decimal floating point, locales other than "C", and the POSIX features listed under POSIX threads.

## How it was made

The work went in phases, each with its research notes, decisions and tests: a conforming library (1), a size pass (2), a speed pass (3), a comparison with Arm Optimized Routines (4), speed follow-ups (5), a minimal POSIX subset and C++ support (7), faster sine and cosine (8 and 9) and POSIX threads (10). The goals, the architecture, every decision (D1 to D158) and the open questions are in `docs/plan/PLAN.md`, and a research note for each algorithm is in `docs/research/`.
