rtoskit-libc 0.5.1 is a build-system release: the library's code, headers and ABI are the same as in 0.5.0, and the prebuilt archives match it. It adds a way for a parent build to pass its own compiler flags to the library.

## New

- **`LIBC_EXTRA_CFLAGS`** (issue #136, PLAN D160): compiler flags a parent build adds to the library's own, for the C sources of `libc.a`, its flavour archives and the port archives. A toolchain build that wants every library function to carry unwind tables and its name in the code passes:

  ```make
  $(MAKE) -C $(LIBC_DIR) ... ARCH_CROSS=armv8-m.main BUILD_TYPE=release \
  	LIBC_EXTRA_CFLAGS="-funwind-tables -mpoke-function-name" library
  ```

  The flags go after the library's (`-ffreestanding -fno-builtin ...`), so the parent no longer has to restate them in `CFLAGS` or put them in `CC`. They do not reach the assembler sources, the link or the test programs. Run `make clean` after changing them, as for `LIBC_MALLOC`. The variable is empty by default, and the size baselines and budgets are measured without it.

## Documentation

- The README's build options and "Building from another project", and `docs/configuration.md`, now list `LIBC_EXTRA_CFLAGS` and `LIBC_UNWIND_TABLES`.
- The README is brought up to date for 0.5: POSIX threads and the POSIX subset, a section on the prebuilt release archives, and the decision log and phases through phase 10.

## Build and CI

- The release workflow uses actions that run on Node 24 (`actions/attest-build-provenance@v4`, `actions/download-artifact@v8`, `actions/upload-artifact@v7`).

## Downloads

As for 0.5.0: one archive per architecture, `rtoskit-libc-0.5.1-<arch>.tar.xz`, holding the `release` and `speed` builds' headers and archives, built without `LIBC_EXTRA_CFLAGS`, with `SHA256SUMS` and a build-provenance attestation for each:

```sh
gh attestation verify rtoskit-libc-0.5.1-armv7e-m.tar.xz --repo sgstreet/rtoskit-libc
```

The 0.5.0 notes describe the library, its architectures and how to use it.
