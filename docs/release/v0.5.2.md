rtoskit-libc 0.5.2 is a fix release for C++ programs. The library's code and ABI are the same as in 0.5.1; one public header changes.

## Fixed

- **`once_flag` was ambiguous in C++** (issue #138, PLAN D161). `<stdlib.h>` declared C23's `once_flag`, `ONCE_FLAG_INIT` and `call_once` in C++ as well as in C. libstdc++'s `<cstdlib>` includes `<stdlib.h>`, so a C++ program with `<mutex>`, anything that reaches `<cstdlib>` (`<string>`, `<cmath>`, `<condition_variable>`, ...) and `using namespace std;` could not name `once_flag`:

  ```cpp
  #include <mutex>
  #include <string>
  using namespace std;
  once_flag f; /* error: reference to 'once_flag' is ambiguous */
  ```

  `<stdlib.h>` now declares them only in C. C programs are unchanged; `<threads.h>`, which C++ does not have, still declares them, and `std::call_once` through `__libc_call_once_eh` is unaffected.

  An audit of every other public header found no other C name that clashes with one in namespace `std`. `test/unit/cxx/std_names.cpp` now checks this for every header but `<threads.h>`.

## Downloads

As for 0.5.0: one archive per architecture, `rtoskit-libc-0.5.2-<arch>.tar.xz`, holding the `release` and `speed` builds' headers and archives, with `SHA256SUMS` and a build-provenance attestation for each:

```sh
gh attestation verify rtoskit-libc-0.5.2-armv7e-m.tar.xz --repo sgstreet/rtoskit-libc
```

A toolchain built against 0.5.1's headers needs only the new `<stdlib.h>`; nothing has to be rebuilt. The 0.5.0 notes describe the library, its architectures and how to use it.
