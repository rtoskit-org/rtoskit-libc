The first release of rtoskit-libc: an ISO C23 (N3220) C standard library for Arm Cortex-M, written clean-room from the standard text and bound to an RTOS through one link-time interface, the `__rtos_*` functions of `include/rtos/rtos-port.h`. Licensed under the MPL-2.0.

It is a 0.x release: the library is complete and tested, but the ABI and the RTOS interface may still change before 1.0 (see "Before 1.0" below).

## What is in it

- **The C23 library a microcontroller can use:** every clause 7 header except the wide-character headers, Annex K and decimal floating point, including the C23 additions (`<stdbit.h>`, `<stdckdint.h>`, `memset_explicit`, `strfromd`, `timegm`), `<stdatomic.h>` and `<threads.h>`.
- **POSIX threads** (`<pthread.h>`, new in phase 10): threads with attributes and scheduling, mutexes (normal, recursive, error-checking, priority-inheriting; timed and clock-selecting), condition variables, keys, `pthread_once`, read-write locks, barriers and spin locks. `<threads.h>` is now a layer over it. No cancellation, signals, `pthread_atfork` or process-shared objects (PLAN D148, D151).
- **A minimal POSIX subset** (PLAN D128): descriptor I/O, `clock_gettime` and friends, `nanosleep`, `sched_yield`, `getentropy`, `<rtoskit-libc.h>` feature macros for libstdc++'s configure, and the C++ runtime hooks (`__cxa_atexit`, `__cxa_thread_atexit`).
- **Correct results:** `printf` and `strtod` are exact at any precision; the float maths functions are correctly rounded and the double ones below 0.53 ulp; floating-point exceptions are raised on every core, including those without an FPU.
- **Small and fast flavours:** the `release` (size) build and the `speed` build of every architecture, and drop-in archives `libc-nofloat.a`, `libc-minimal-printf.a` and `libc-tinymalloc.a`. A size budget gates every change.
- **Two ports:** `librtos-none.a` for bare metal (one thread) and `librtos-linux.a`, the Linux test port the test suite runs on.

## Downloads

One archive per architecture, `rtoskit-libc-0.1.0-<arch>.tar.xz`, each holding the headers and the archives of the `release` and `speed` builds (`<build>/include`, `<build>/lib`):

| Architecture | Cores |
|---|---|
| `armv6-m` | Armv6-M without the OS extension |
| `armv6s-m` | Cortex-M0, M0+ (and M23) |
| `armv7-m` | Cortex-M3; M4 or M33 without an FPU |
| `armv7e-m` | Cortex-M4F; M7 with the single-precision FPU |
| `armv7e-m-dp` | Cortex-M7 with the double-precision FPU |
| `armv8-m.main` | Cortex-M33 with FPU and DSP (M55, M85) |
| `x86_64` | the development host, through the Linux test port only |

Built with arm-none-eabi GCC 16.2 (x86_64: the runner's host GCC). Programs that use the headers must be compiled as C23 (`-std=c23` or `-std=gnu23`) with the same `-march` and `-mfloat-abi` as the archive; see `README.md`. `SHA256SUMS` lists every archive's checksum, and each archive's build provenance can be checked with `gh attestation verify <archive> --repo sgstreet/rtoskit-libc`.

## Before 1.0

- The ABI of `mtx_t` and `cnd_t` changed in phase 10 (PLAN D156): a toolchain's libstdc++ and any RTOS port built against an earlier tree must be rebuilt with this one.
- Phase 10's last step (P10.08) is open: the libstdc++ `posix` thread model for rtoskit-gcc, and pi-pico's move to the new thread interface.
- The library builds only with GCC 14 or newer; compiling programs against it with Clang is untested.

The design, every decision (D1 to D157) and the open questions are in `docs/plan/PLAN.md`; size and speed figures per architecture are in `docs/size/` and `docs/perf/`.
